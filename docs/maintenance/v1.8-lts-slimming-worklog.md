## 本轮判断

当前 LTS 是用户行为、浏览器存储、图片、路由、主题和离线交付的唯一事实源。旧 slim 只证明了若干拆分边界可行，不再是可以整体合并或直接复制的实现源。

本轮不把三条历史分支重新合流。实施方式是：在当前 LTS 上先锁定行为，再按旧 slim 的提交证据重新完成模块化；每一批改动独立验证并提交。

确定性结果、自动化缺口和分批门禁见[测试基线](../testing/v1.8-lts-slimming-baseline.md)。

## 旧实现不能直接信任的代码证据

旧 slim 的拆分模块仍绑定桌面时代依赖：

- `useWeaponDraftPageController.tsx`、`useEquipmentImagePicker.ts`、`operatorDraftPageModel.ts` 等依赖已从 LTS 删除的 `imageBridge`。
- 多个 model/controller 直接读写 `window.localStorage`；当前 LTS 使用 SQLite-backed `persistentLocalStorage`，并在启动时统一 hydrate/flush。
- 旧 SkillButton 冒烟手册要求 Electron SQLite transport；当前 LTS 的 Timeline 与 Work Node 已迁入浏览器 SQLite。
- 旧 slim 没有 LTS 后续的 route lazy loading、Web App shell、Web Locks、PWA、浏览器图片库和主题运行时。
- 旧 slim 的 Damage Sheet/ExcelJS 删除是产品取舍，不是行为等价的纯重构。

因此，旧代码只能用于识别职责边界、函数集合和拆分顺序；任何复制到 LTS 的实现都必须重新接入当前平台层并由当前测试证明。

## 新实施顺序

1. 固定 LTS 确定性基线，并补浏览器行为测试骨架。
2. 删除仍不可达的旧 Buff 编辑器；不同时改当前 Buff Sheet。
3. 先从当前 Buff、Weapon 页面抽稳定目录常量；目录是纯数据边界，应早于 controller/view 拆分。
4. 将 Buff、Weapon、Equipment 分成三个独立迁移批次；每页依次抽纯 model、持久化 adapter、controller 和 view，再抽 share/formula/explorer。
5. 拆 OperatorDraft，再拆 BuffBatch；两者分别保留浏览器图片库和批量选择语义。
6. 以当前 LTS 为源拆 SkillButton，保护主题 DOM、详情路由和 Timeline SQLite 持久化；不复制旧分支的总控 runtime hook。
7. 在功能继续保留的前提下，按需拆 Damage Sheet 的 projection/undo；这一轮不得删除页面或 ExcelJS。
8. 单独做 Damage Sheet/ExcelJS 产品决定；只有所有导出消费方归零并通过对应验收后才能移除 ExcelJS。
9. 最后评估旧 slim 未完成的 CanvasBoard 和 OperatorConfig。

### 2. 抽取 Buff 与 Weapon 稳定目录

### 3. 固定 Buff 模型行为并修复归一化幂等

- 触发方式：新增旧 `buffs` schema、倍率/计层、额外伤害段、ID、不可变重排和 row projection 的 characterization test。
- 基线缺陷：`15%法术脆弱` 再次 normalize 后会变成 `15%`，与原代码“必须幂等”的注释和用户显示名保留目标冲突。
- 根因：重复数值清理正则嵌入外层分组后仍使用 `\\1`，实际反向引用了可为空的分隔符分组，把单个数值误判为重复值。
- 修复：重复 token 改为捕获组 2 并使用 `\\2`；只修正分组引用，不改变正常自动命名、旧类型迁移或数值格式。
- 验证：新增测试证明旧 schema 一次迁移后再次 normalize 完全不变；全量 Node、浏览器、build 与离线壳门禁通过。
- 留痕判断：这是测试在当前 LTS 上发现的独立缺陷，不属于旧 slim 的结构改动，因此单独提交后再开始 model 搬迁。
