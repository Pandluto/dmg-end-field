# 1.8 Slim 独立桌面 Shell 实施账本

- 建立日期：2026-08-06
- 实施分支：`codex/v1.8-lts-desktop-shell`
- 浏览器前端基线：`codex/v1.8-lts-slimming`
- 方案事实源：[`v1.8-slim-electron-shell-migration-20260806.md`](../architecture/audits/v1.8-slim-electron-shell-migration-20260806.md)

## 最终边界

1. Electron 只显示独立 Shell，不显示 Slim 业务页面。
2. Slim LTS 由系统浏览器访问；开发端口为 `3030`，生产固定为 `31457`。
3. 浏览器 SQLite WASM + OPFS 是唯一业务数据库。
4. Slim 自己负责主题、工作区、存档、备份、图片和资料。
5. Shell 只负责浏览器唤起、静态宿主、托盘、单实例、Shell 缩放、退出和发包工具。
6. Agent/OpenCode 与 MCP 只有占位；旧 Node SQLite 和旧 AI/MCP 运行时均不移植。
7. CI/CD、自动发布、自动更新、签名和公证流水线暂缓。

## 纠偏记录

初版曾按“Electron BrowserWindow 直接加载 Slim App”实施，并把 Shell 信息、缩放和发包工具放进 Slim 设置页。用户澄清旧产品本来就是独立 Shell 唤起系统浏览器后，本轮已整体纠正：

- Electron 改为加载 `electron/shell/index.html`；
- Slim 设置页移除 Electron 专属面板；
- preload 只注入独立 Shell；
- 系统浏览器明确断言拿不到 `desktopHost`；
- 退出流程不再假装能要求外部浏览器 flush 数据。

## 关键实现事实

### Electron

- Electron BrowserWindow 的页面是本地 `file://.../electron/shell/index.html`。
- Shell renderer 启用 sandbox 和 context isolation，关闭 Node 与 webview。
- IPC 同时校验 Shell WebContents 与固定 Shell 文件，外部浏览器无法调用。
- 关闭窗口只隐藏 Shell；托盘负责恢复和完全退出。
- 生产模式启动 `dist` 的 loopback 静态宿主，开发模式复用 Vite `3030`。

### 浏览器

- Shell 打开 `http://127.0.0.1:3030/?__desktop_shell=1` 或 `http://127.0.0.1:31457/?__desktop_shell=1`。
- 本地模式跳过公开网站门禁和远端页面更新入口。
- 页面仍显示 Web LTS 语境，仍使用浏览器 SQLite/OPFS、持久存储和 SQLite 备份。
- 浏览器页面没有 Electron preload，也不显示发包工具。

### 发包与依赖

- 图片工具生成 `assets-release-manifest.json` 与 ZIP。
- 数据工具从完整 `data/` 或 `public/data/` 生成 `web-data-manifest.json` 与 ZIP。
- Native Dialog 是源目录和输出目录的唯一授权来源。
- 安装包排除 `node_modules`、Web App Shell `sw.js`、`src`、`agent` 和旧 Node SQLite/AI/MCP runtime。

## 使用方式

```bash
npm run electron:dev
```

启动后看到的是独立 Shell。点击“打开浏览器工作台”后，Slim LTS 才会出现在系统浏览器中。
