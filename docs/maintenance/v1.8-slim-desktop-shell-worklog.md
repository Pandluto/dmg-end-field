# 1.8 Slim 桌面壳实施账本

- 建立日期：2026-08-06
- 实施分支：`codex/v1.8-lts-desktop-shell`
- 前端基线：`codex/v1.8-lts-slimming@622d4cf1`
- 方案事实源：[`v1.8-slim-electron-shell-migration-20260806.md`](../architecture/audits/v1.8-slim-electron-shell-migration-20260806.md)

## 不可变边界

1. Slim 的 SQLite WASM + OPFS 是唯一业务数据库。
2. 旧 Node SQLite、数据服务、Timeline repository、Work Node store、迁移器和双写路径全部不移植。
3. 桌面页面始终来自安装包内的固定 loopback 静态服务器，不实现 Web 断网 App Shell、离线恢复或页面更新。
4. Service Worker 在桌面模式下只服务图片、资料和可选主题缓存，不接管导航、HTML、JS 或 CSS。
5. OpenCode/Agent 与 MCP 本轮只有统一 capability 占位，不启动进程、不监听端口、不打包运行时。
6. CI/CD、自动发布和桌面自动更新暂缓。

## 验证口径

- 不新增断网、离线 App Shell 或 CI/CD 测试。
- 业务正确性继续复用 Slim 的类型、单元、数值和关键 E2E。
- 桌面专项只验证本地宿主、资源交付、SQLite/OPFS 重启恢复、最小 IPC、发包工具和旧运行时不可达。
- 每个实现批次独立提交，并在本账本记录命令与结果。

## 长期同步规则

- Slim LTS 是共享前端的唯一上游；普通页面、计算、SQLite schema、图片库和资料包修复先进入 Slim LTS。
- 桌面分支只维护 `electron/**`、桌面 capability、桌面资源 Worker 和未来 Agent/MCP 模块。
- 同步 LTS 时只做有记录的前向合并，不在桌面分支另写一份业务页面。

## 实施结果

### 桌面宿主

- `electron/main.cjs` 重写为 423 行薄入口；旧基线为 6,843 行。
- 生产页面固定来自 `http://127.0.0.1:31457/`，开发页面来自 `3030`；固定 origin 不回退到随机端口。
- 保留单实例、窗口、托盘、缩放和退出前 flush；Renderer 启用 sandbox、context isolation，关闭 Node 与 webview。
- preload 只有 26 行、11 个 request/response IPC handler；调用同时校验 WebContents 与固定 origin。
- Main 每次启动只移除旧 Service Worker 注册，不清 CacheStorage、OPFS 或业务数据。

### Slim 前端适配

- Electron 直接渲染与 Web 相同的 `AppProvider + App`，没有第二套 Shell 页面。
- 桌面模式跳过网站访问门禁、页面版本检查、Web 离线状态与更新 UI。
- 首次资料和图片从安装包载入，业务数据库仍是 SQLite WASM + OPFS。
- `/sw-desktop.js` 只处理图片、资料和可选主题；导航、HTML、JS、CSS 与普通静态资产始终回源到当前安装包。
- 设置页显示 Desktop LTS、宿主版本、缩放、Agent/OpenCode 与 MCP 的明确占位，以及两种发包工具。

### 发包与打包边界

- 图片工具生成既有 `assets-release-manifest.json` 与 ZIP；数据工具从完整 `data/` 或 `public/data/` 生成 `web-data-manifest.json` 与 ZIP。
- 两个工具只读取 Native Dialog 实际选中的目录，不接受 Renderer 自报路径，不访问 OPFS、CacheStorage 或旧 Node SQLite，并拒绝会与源目录重叠的破坏性输出路径。
- 安装包只包含 Slim `dist`、6 个 Electron Shell 文件、两个发布 builder 与 `package.json`。
- 安装包明确排除 `node_modules`、Web App Shell `sw.js`、`src`、`agent`、旧 Node SQLite、sidecar、Agent/OpenCode 与 MCP runtime。

## 本轮保留项

- OpenCode/Pi Agent 与 MCP 只完成 capability 和 UI 占位，运行时实现留给后续独立阶段。
- CI/CD、自动上传 GitHub Release、桌面自动更新、签名和公证流水线仍按约定暂缓。
- 本轮环境完成 macOS arm64 真包验证；Windows portable 配置已保留，但 Windows 真机验收仍需在对应平台进行。
- 桌面端不承担 Web 站点的断网 App Shell 与离线恢复测试；安装页面随本地 Electron 进程提供。
