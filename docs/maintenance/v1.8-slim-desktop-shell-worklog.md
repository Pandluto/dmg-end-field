## 不可变边界

1. Slim 的 SQLite WASM + OPFS 是唯一业务数据库。
2. 旧 Node SQLite、数据服务、Timeline repository、Work Node store、迁移器和双写路径全部不移植。
3. 桌面页面始终来自安装包内的固定 loopback 静态服务器，不实现 Web 断网 App Shell、离线恢复或页面更新。
4. Service Worker 在桌面模式下只服务图片、资料和可选主题缓存，不接管导航、HTML、JS 或 CSS。
5. OpenCode/Agent 与 MCP 本轮只有统一 capability 占位，不启动进程、不监听端口、不打包运行时。
6. CI/CD、自动发布和桌面自动更新暂缓。

## 验证口径

- 不新增断网、离线 App Shell 或 CI/CD 测试。
- 业务正确性继续复用 Slim 的类型、单元、数值和关键 E2E。
- 桌面专项只验证本地宿主、资源交付、SQLite/OPFS 重启恢复、最小 IPC、发包工具和旧运行时不可达。
- 每个实现批次独立提交，并在本账本记录命令与结果。

## 长期同步规则

- Slim LTS 是共享前端的唯一上游；普通页面、计算、SQLite schema、图片库和资料包修复先进入 Slim LTS。
- 桌面分支只维护 `electron/**`、桌面 capability、桌面资源 Worker 和未来 Agent/MCP 模块。
- 同步 LTS 时只做有记录的前向合并，不在桌面分支另写一份业务页面。
