# 1.8 Slim 独立桌面 Shell 实施账本

- 建立日期：2026-08-06
- 实施分支：`codex/v1.8-lts-desktop-shell`
- 浏览器前端基线：`codex/v1.8-lts-slimming`
- 方案事实源：[`v1.8-slim-electron-shell-migration-20260806.md`](../architecture/audits/v1.8-slim-electron-shell-migration-20260806.md)

## 最终边界

1. Electron 只显示独立 Shell，不显示 Slim 业务页面。
2. Slim LTS 由系统浏览器访问；开发端口为 `3030`，生产固定为 `31457`。
3. 浏览器 SQLite WASM + OPFS 是唯一业务数据库。
4. Slim 自己负责主题、工作区、存档、备份、图片和资料。
5. Shell 只负责浏览器唤起、静态宿主、托盘、单实例、Shell 缩放、退出和发包工具。
6. Agent/OpenCode 仍为占位；Legacy Fill MCP 已按窄边界恢复，旧 Node 业务 SQLite、旧 REST 和 DEF runtime 不移植。
7. CI/CD、自动发布、自动更新、签名和公证流水线暂缓。

## 纠偏记录

初版曾按“Electron BrowserWindow 直接加载 Slim App”实施，并把 Shell 信息、缩放和发包工具放进 Slim 设置页。用户澄清旧产品本来就是独立 Shell 唤起系统浏览器后，本轮已整体纠正：

- Electron 改为加载 `electron/shell/index.html`；
- Slim 设置页移除 Electron 专属面板；
- preload 只注入独立 Shell；
- 系统浏览器明确断言拿不到 `desktopHost`；
- 退出流程不再假装能要求外部浏览器 flush 数据。

## 关键实现事实

### Electron

- Electron BrowserWindow 的页面是本地 `file://.../electron/shell/index.html`。
- Shell renderer 启用 sandbox 和 context isolation，关闭 Node 与 webview。
- IPC 同时校验 Shell WebContents 与固定 Shell 文件，外部浏览器无法调用。
- 关闭窗口只隐藏 Shell；托盘负责恢复和完全退出。
- 生产模式启动 `dist` 的 loopback 静态宿主，开发模式复用 Vite `3030`。
- Legacy Fill daemon 使用 Electron `utilityProcess.fork`，不依赖成品 App 的 `ELECTRON_RUN_AS_NODE` 行为。

### 浏览器

- Shell 打开 `http://127.0.0.1:3030/?__desktop_shell=1` 或 `http://127.0.0.1:31457/?__desktop_shell=1`。
- 本地模式跳过公开网站门禁和远端页面更新入口。
- 页面仍显示 Web LTS 语境，仍使用浏览器 SQLite/OPFS、持久存储和 SQLite 备份。
- 浏览器页面没有 Electron preload，也不显示发包工具。

### 发包与依赖

- 图片工具生成 `assets-release-manifest.json` 与 ZIP。
- 数据工具从完整 `data/` 或 `public/data/` 生成 `web-data-manifest.json` 与 ZIP。
- Native Dialog 是源目录和输出目录的唯一授权来源。
- 安装包排除 `node_modules`、Web App Shell `sw.js`、`src`、`agent` 和旧 Node 业务 SQLite/AI runtime；Legacy Fill MCP 的可执行文件明确解包到 `app.asar.unpacked/dist/legacy-fill/**`。

### Legacy Fill MCP

- Electron 只监管 MCP 子进程、私有客户端配置和独立 `legacy-fill.sqlite3`；该库不保存正式业务资料。
- 普通工作页仅能发布四域快照，不能读取提案或执行审核。
- Shell 每次打开审核页都会签发 30 秒、单次使用的 fragment grant；页面立即移除 grant 并交换审核 session。
- 已有工作页占用 OPFS writer 时，Shell 唤起的审核页会请求原页先 flush、关闭连接，再自动接管。
- 写入按“CAS → prepared outbox flush → 产品资料 flush → 重读后置条件 → 发布 snapshot → 记录 saved → 清 outbox”执行。
- 武器、干员和装备更新保留现有图片 URL；成功后同时发送当前 `local-library-changed` 事件。

## MCP 审核页适配（2026-08-06）

- 审核页改为独立响应式页面边界，不再受主工作台 `1440px` 最小宽度影响。
- 页面网格会根据提示条是否出现切换两行/三行结构；空队列和有提示两种状态都必须铺满浏览器可用高度。
- 待处理/全部记录、搜索与当前选择保持同步，不会出现选中项被筛掉后详情残留。
- 已有资料默认展示字段级前后对比；新增资料、完整写入结果和提案依据分别可核对。
- 差异生成会忽略规范化对象中的 `undefined` 可选字段，避免“原来不存在、写入后仍不存在”的伪变更。
- 服务未就绪、提案过期、版本冲突或内容校验失败时，确认写入会被阻止；错误与提醒均展示具体内容。
- Electron 烟测覆盖 1440px 与 760px 页面布局、已有资料的字段对比/拒绝流程，并继续完成 Buff、武器、干员、装备四域的真实 SQLite 往返。
- Electron 烟测额外断言空队列与成功提示状态下工作区底边必须贴合浏览器视口底边，防止再次出现半屏页面。
- 审核模型契约覆盖筛选、选择恢复、校验规范化、写入门禁、差异路径和值格式化。
- 真实 Chrome 在 90% 缩放和纸墨主题下完成排版复核；审核页改用本地系统 UI 字体，提高卡片小标题、状态、页签和说明文字的字号、字重与对比度，ID 与时间仍保持次要层级。
- 右侧不再重复队列已有的领域、状态、名称、摘要和时间；原提案标题区被合并为 48px 的“视图页签 + 检查状态”工具栏，结果预览也移除重复资料名，让首个真实结果直接进入宽屏首屏。Electron 烟测固定断言工具栏不超过 52px、重复标题区不存在且首个结果位于 500px 以内。

macOS 本地验证包因环境没有 Developer ID 而未签名、未公证；这不影响本轮结构与功能冒烟结果。

## 使用方式

```bash
npm run electron:dev
```

启动后看到的是独立 Shell。点击“打开浏览器工作台”后，Slim LTS 出现在系统浏览器中；点击“打开 MCP 填表”会另行签发一次性授权并打开隐藏审核页。
