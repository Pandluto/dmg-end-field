## 结论

第二轮把 1.8 LTS 收口为一个本地数据工作台：保留 React 工作台、SQLite、排轴、Work Node、数据包、图片管理与伤害计算；移除 DEF/OpenCode/Harness、旧 AI CLI、MCP/Legacy Fill 以及它们的运行、界面、测试和发布链。

当前变更删除 6,297 个受 Git 跟踪的文件，共 97,904,611 字节（93.37 MiB）和约 122 万行。另有一批未跟踪或被忽略的 OpenCode 二进制、UI 构建产物与 Bun 临时文件从 `agent/` 清除；这些生成物不计入 Git 删除统计。

## 删除明细

| 范围 | 删除内容 |
| --- | --- |
| Agent 运行时 | 整个 `agent/`：DEF server、OpenCode adapter/core/UI、Harness、Skills、typed tools、会话协议和 vendored OpenCode 源码 |
| MCP / Legacy Fill | `src/legacyFill*`、MCP 页面与结果预览、stdio/service/runtime、合同脚本及迁移说明 |
| 前端入口 | AI CLI、DEF OpenCode、MCP 路由、导航按钮、工作台 AI 面板、相关状态与样式 |
| Electron | Agent/AI REST/MCP sidecar、端口与健康检查、代理/SSE/interop 路由、Legacy Fill IPC 与启动预热 |
| 构建发布 | OpenCode/MCP 构建脚本、打包资源、依赖、sidecar smoke、Release 中的 Bun/vendor/snapshot job |
| 开发材料 | `.agents/` Harness 审计辅助、DEF 黑盒说明、MCP/Legacy Fill 当前合同与已退出架构文档 |

删除的本地服务端口包括旧 Agent、AI REST、MCP 和 Legacy Fill 使用的 `17321`、`17322`、`17323` 及 `17445` 起始端口段。Electron 只保留工作台本地 bridge 和 Shell 所需的能力。

## 明确保留

- `src/` 中的主工作台、选择页、Operator Studio、装备/武器/Buff 编辑与计算链；
- `electron/timeline-repository.cjs` 的 Timeline、Work Node、revision/CAS、备份和迁移能力；
- SQLite catalog、用户 Timeline SQLite、数据管理、数据 Release 与图片 Release；
- Shell 的概览、数据、图片和日志页面；
- `data/sharedata/**`、`.runtime/**` 以及用户 AppData 中的数据库和私人排轴。

## 数据与兼容性边界

本轮没有打开、改写或清除任何用户数据库，也没有执行删除旧表的迁移。旧数据库中如果已经存在 Agent session binding 表，它会原样留在用户文件里，但 1.8 LTS 不再创建、读取或更新该表。

代码中仍保留少量 `def.*`、`ai-timeline-*` 和 `mainWorkbench` 名称。这些名称属于既有 IPC、localStorage、数据库文件名或内部模块兼容层，不表示 DEF/OpenCode/MCP 运行时仍然存在。为避免破坏已有私人排轴，本轮不做存储键和文件名迁移。

依赖审计为 0 个 high/critical。ExcelJS 的间接 `uuid` 依赖仍报告 2 个 moderate；上游当前只提供会把 ExcelJS 降至 3.4.0 的强制修复，因此本轮不做破坏性降级。Web build 仍有既有的单 chunk 体积和 `assetResolver` 混合导入提示。

打包启动仍会报告 Electron 内置 SQLite experimental、`fs.Stats` deprecated 和 `console-message` deprecated 警告；本轮功能 smoke 不受影响，后续 LTS 稳定化需要继续消除这三项运行时告警。

## 恢复方式

受 Git 跟踪的删除内容可从起始基线 `073132d55d9253cb45c366b3beb93425f5330557` 恢复。未跟踪的 OpenCode 构建产物需要从对应历史源码重新构建，不承载用户数据。

本轮没有推送或覆盖远端分支，也没有修改 `data/sharedata/**`。
