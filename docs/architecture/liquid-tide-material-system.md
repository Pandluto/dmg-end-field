# 潮汐玻璃材质系统

本文记录 `liquid-tide` 主题的材质边界、真实液态玻璃入口和 2026-08-01 的浏览器验收结果。它是当前实现事实，不是新一轮 Spec。

## 为什么重做

旧版主题在大量卡片、表格行、工具栏和外层面板上分别使用 `backdrop-filter`。多个模糊层叠加后既不像液态玻璃，也会让界面发灰、文字变糊，并增加浏览器合成开销。

本轮抽样基线中：

| 页面 | 可见模糊层 | 嵌套模糊层 |
| --- | ---: | ---: |
| 主排轴 | 28 | 11 |
| 干员配置 | 16 | 14 |
| PPT 报表 | 81 | 76 |

## 三层材质规则

### 1. 真实液态玻璃

只用于悬浮、可点击、需要从背景中浮起的控件或紧凑操作组：导航 Dock、页签组、工具条、弹窗标题操作区、主题选项、配置头像条、批量 Buff 工具按钮等。

- 渲染器为 `@ybouane/liquidglass`，不是 CSS 模糊的视觉冒充。
- 每个控件按实际屏幕位置使用一张不可见 Canvas 取景；Canvas 不参与页面绘制，只向 WebGL 提供背景像素，因此不会出现矩形背景穿帮。
- 同一父节点下的按钮组共享一个渲染实例；单个主题根最多管理 12 个实例，避免无界创建 WebGL 上下文。
- WebGL 或背景资源不可用时降级为清晰的半透明实体，不回退到多层磨砂。
- 拖拽、滚动和缩放后重新对齐取景；普通鼠标移动不会持续重绘。
- 页面切换或目标离开视口后销毁渲染实例，并显式释放对应的 WebGL 上下文，避免长时间使用耗尽浏览器上下文额度。

入口：

- `src/platform/theme/useLiquidTideSurfaceGlass.ts`
- `src/platform/theme/useLiquidTideGlass.ts`（排轴技能按钮的不规则圆方一体轮廓）

### 2. 单层阅读承载

数据密集区域可以保留一层低成本磨砂，用来稳定文字对比度。一个视觉区域只允许一个承载层，例如：

- 主排轴右侧业务栏；
- 选择页的干员列表与资料库；
- 干员草稿整页；
- 表格页的 Ribbon、资源树和工作表；
- 图片管理器的资源树、表格与预览区；
- 应用的开始、数据、设置窗口。

承载层内的卡片、列表项、表格单元格和统计行不得再次模糊。

干员配置总面板、技能详情标题与左/中/右三列属于布局骨架：保持透明，只用双明度细边框保证它们在图片的明暗区域都能识别。真实内容卡可以使用低透明填色，但不得把整条或整列布局容器做成磨砂板。

添加 Buff 工作台的整页外壳同样属于布局骨架。顶部模式切换可以使用真实液态玻璃，但镜片宽度必须贴合按钮内容，不能填满剩余空行。

透明骨架不能直接覆盖另一层可读业务界面。技能详情覆盖主排轴时，由详情根节点提供唯一一张全屏高斯磨砂门板；继续打开添加 Buff 时，父级门板停用，由最上层搜索遮罩接管整屏模糊。每个覆盖深度只允许一张门板，列、卡片与占位 `div` 不再分别模糊。

### 3. 清晰内容层

卡片、行、单元格、网格、表单和图表使用透明或低透明填色、边界与状态色建立层次，不使用 `backdrop-filter`。PPT 页面作为导出画布采用高可读半透明底色，也不做大面积实时模糊。

## 覆盖范围

真实液态玻璃注册表当前覆盖：

- 开始、数据、设置窗口的页签、关闭按钮、操作组和主题选项；
- 主排轴顶部页签、底部导航、沙盒工具条和所有技能按钮；
- 选人页头部操作、确认按钮、已选卡、搜索 Dock 与底部操作；
- 干员配置的返回、头像切换和 CTI 搜索条；
- 技能详情顶部工具 Dock、展开按钮、目标抗性/信息 Popover、Buff 批量操作和添加 Buff 模式切换；
- 技能详情计算乘区保留原 SVG 导航，在每个 SVG 节点正下方配置同尺寸真实液态玻璃取景层；旧 SVG 矩形只保留透明命中区，不绘制第二套边框；
- 批量 Buff 左侧工具按钮、右侧干员按钮与底部导航；
- 干员/Buff/武器/装备草稿操作组；
- 伤害表、PPT、图片管理器与常用弹窗的顶栏或操作组；
- 悬浮 Logo 与菜单。

大型列表项、工作流卡片、数据工具卡和整张表格不注册 WebGL；它们属于内容层。

## 维护约束

1. 新增液态玻璃目标时，优先注册一组操作控件，而不是一整块内容卡。
2. 不允许为了折射增加可见的背景复制层；背景只能由不可见 Canvas 提供。
3. 不允许在阅读承载层内部再启用模糊。需要区分层级时使用透明度、边框、状态色和留白。
4. 不给干员、装备、武器、技能图标或其他彩色原图增加滤镜或统一蒙版。
5. 任何主题改动都要复核技能详情、添加 Buff、批量 Buff、数据表格、图片管理和 PPT，而不只看主排轴。
6. 低透明度环境使用实体降级；降级仍须保持内容可读和按钮状态可辨。
7. 纯布局 `div` 不得因为尺寸较大就自动升级为磨砂承载层；优先使用透明背景与可辨识边框。
8. 透明覆盖界面必须由一张全屏门板隔离下层内容；嵌套覆盖时由最上层门板接管，不叠加多张全屏模糊。
9. 计算摘要、计算行与 Buff 内容行属于文字层；允许分隔线，不允许再用半透明卡底和阴影模拟额外磨砂。
10. 乘区列表滚轮按最高 960px/s 逐帧推进，并限制卡顿后的单帧补偿，确保高刷新率屏幕和快速滚动下，新进入视口的真实玻璃目标仍有时间完成取景与注册。
11. 直接落在整屏磨砂承载层上的伤害组成、计算标签、公式值与 Buff 说明统一使用深墨文字；浅灰与浅紫只用于真实液态玻璃内部或明确的交互状态。
