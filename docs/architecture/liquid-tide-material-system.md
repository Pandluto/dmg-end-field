# 潮汐玻璃材质系统

本文记录 `liquid-tide` 主题的材质边界、真实液态玻璃入口和 2026-08-01 的浏览器验收结果。它是当前实现事实，不是新一轮 Spec。

## 为什么重做

旧版主题在大量卡片、表格行、工具栏和外层面板上分别使用 `backdrop-filter`。多个模糊层叠加后既不像液态玻璃，也会让界面发灰、文字变糊，并增加浏览器合成开销。

本轮抽样基线中：

| 页面 | 可见模糊层 | 嵌套模糊层 |
| --- | ---: | ---: |
| 主排轴 | 28 | 11 |
| 干员配置 | 16 | 14 |
| PPT 报表 | 81 | 76 |

## 三层材质规则

### 1. 真实液态玻璃

只用于悬浮、可点击、需要从背景中浮起的单一控件，以及少数已经确认需要透出底图的业务图窗：导航按钮、页签按钮、弹窗关闭按钮、主题选项、配置头像条、批量 Buff 工具按钮等。

工具栏、页签栏和标题栏只是排列这些控件的透明骨架，不能整条注册为一个镜片。即便几个按钮在视觉上相邻，每个按钮也必须保持独立的折射轮廓；恢复列表、数据行与说明文字不得因为同处一个圆角容器就获得真实玻璃。

- 渲染器为 `@ybouane/liquidglass`，不是 CSS 模糊的视觉冒充。
- 每个控件按实际屏幕位置使用一张不可见 Canvas 取景；Canvas 不参与页面绘制，只向 WebGL 提供背景像素，因此不会出现矩形背景穿帮。
- 库要求玻璃目标必须是渲染根的直接子元素；满足该结构的同组按钮共享一个渲染实例。单个主题根最多管理 16 组镜片，首次生成由质量档位控制的小型并发池执行，不会同时持有 16 个 WebGL 上下文。
- WebGL 或背景资源不可用时降级为清晰的半透明实体，不回退到多层磨砂。
- 拖拽、滚动和缩放结束后重新对齐取景；滚动过程中沿用随 DOM 一起移动的稳定镜片，普通鼠标移动和每一帧滚动都不会触发 WebGL 重绘。
- 主排轴技能按钮、工作台固定控件和干员配置固定镜片在首次真实折射稳定后，按视口、位置、尺寸、镜片类型与材质参数整组记录画面，并立即销毁生成该画面的渲染实例。前景文字、图标和业务状态继续由实时 DOM 绘制，不会被截图冻结；记录同时进入内存 LRU 和浏览器 IndexedDB，返回页面、重新打开相同配置乃至刷新页面都直接还原 PNG 镜片数据，不创建新的 WebGL 实例。
- 页面切换、几何失效或首次稳定帧完成后都会显式释放对应的 WebGL 上下文，避免等待垃圾回收期间耗尽浏览器上下文额度。

入口：

- `src/platform/theme/useLiquidTideSurfaceGlass.ts`
- `src/platform/theme/useLiquidTideGlass.ts`（排轴技能按钮的不规则圆方一体轮廓）

### 2. 单层阅读承载

数据密集区域可以保留一层低成本磨砂，用来稳定文字对比度。一个视觉区域只允许一个承载层，例如：

- 主排轴右侧业务栏；
- 选择页的干员列表与资料库；
- 干员草稿整页；
- 表格页的 Ribbon、资源树和工作表；
- 图片管理器的资源树、表格与预览区；
- 应用的开始、数据、设置窗口。

承载层内的卡片、列表项、表格单元格和统计行不得再次模糊。

干员配置总面板、技能详情标题与左/中/右三列属于布局骨架：保持透明，只用双明度细边框保证它们在图片的明暗区域都能识别。真实内容卡可以使用低透明填色，但不得把整条或整列布局容器做成磨砂板。

添加 Buff 工作台的整页外壳同样属于布局骨架。顶部模式切换可以使用真实液态玻璃，但镜片宽度必须贴合按钮内容，不能填满剩余空行。

透明骨架不能直接覆盖另一层可读业务界面。技能详情覆盖主排轴时，由详情根节点提供唯一一张全屏高斯磨砂门板；继续打开添加 Buff 时，父级门板停用，由最上层搜索遮罩接管整屏模糊。每个覆盖深度只允许一张门板，列、卡片与占位 `div` 不再分别模糊。

### 3. 清晰内容层

卡片、行、单元格、网格、表单和图表使用透明或低透明填色、边界与状态色建立层次，不使用 `backdrop-filter`。PPT 页面作为导出画布采用高可读半透明底色，也不做大面积实时模糊。

## 选材判定

以“上 Buff”界面为基准，先判断组件职责，再决定材质；不能按照 `div` 的大小或圆角逐层加磨砂。

| 场景 | 材质 | 典型对象 |
| --- | --- | --- |
| 悬浮且可操作，或需要让图片透出的单一中层 | 真实液态玻璃 | 单个页签、返回、确认、关闭、恢复行操作、装备/武器/潜能图窗与操作轨 |
| 整页覆盖了仍可阅读的下层业务 | 一层全屏磨砂门板 | 技能详情、上 Buff、保存/恢复、节点与报表弹窗、干员配置 |
| 同一页面有独立且长期承载密集文字或图片的区域 | 一层局部磨砂承载 | 主排轴右栏、资源树、工作表；前提是它没有嵌在另一张局部磨砂里 |
| 已经位于门板或承载层之内 | 透明骨架或低透明内容 | 列框、卡片、统计行、表格单元格、输入框、装备字段 |

同一像素路径最多允许两层磨砂：一张当前覆盖页的全屏门板，以及一张确有阅读职责的局部承载层或下层既有业务承载层。第二层不是为了给子卡片“加质感”；只有文字压在高变化图片或真实液态镜片上、单靠门板仍无法稳定阅读时才启用。其他情况继续使用边框、低透明填色和状态色。真实液态玻璃不作为阅读磨砂层计数，也不能拿来包裹整列文字内容。

干员配置的装备区与武器区采用同一层级：装备大框和内侧舞台都是透明结构框；四张装备图分别使用独立的真实液态窗口，原图保持原色；词条文字只使用无模糊的低透明读数框，每条加点胶囊轨分别使用真实液态窗口，并与武器胶囊共享 current / lit / dim 三态配色。每个装备槽内的三条胶囊轨是同一直接父节点下的三个真实镜片，四个槽位分别保留有效渲染实例。三个词条框与三条胶囊轨已经各自形成边界，外侧不再套第七层总框。技能和角色等级的横向胶囊也使用同一三态配色，其中最后一个已点亮胶囊承担 current 状态；角色等级胶囊轨本身是一张紧凑液态窗口。主能力与副能力不增加模糊，通过粉、蓝两档 2px 语义边框区分。禁止再给整个装备舞台或整组词条叠加白色磨砂。

武器选择、潜能和配置区域已经位于干员配置的全屏磨砂门板上，因此外层只保留透明框架，不再添加白色填充、阴影或第二层模糊；名称、类型、等级、说明与配置文字直接落在门板上。胶囊配置轨继续作为独立液态窗口；三条武器胶囊轨因各自位于不同直接父节点而保留三个真实渲染实例，不能用跨层管理根伪装共享。武器原图、武器潜能图形和角色潜能图形也分别使用独立的真实液态窗口，武器图窗与潜能图窗都纵向顶满各自框架，原图与 SVG 本身保持清晰且不改变图形结构。CTI 外壳保持透明，只有宽度受控的搜索输入和展开结果承担局部磨砂。

## 覆盖范围

真实液态玻璃注册表当前覆盖：

- 开始、数据、设置窗口的独立页签、关闭按钮、操作按钮和主题选项；
- 主排轴顶部页签、底部每个导航与工具按钮、沙盒工具按钮和所有技能按钮；
- 选人页头部操作、清空、确认、移除与底部操作；干员卡和搜索栏保持内容层；
- 干员配置的返回、角色等级胶囊轨、换人平行四边形、四张装备图片、装备与武器胶囊轨、武器图片及两组潜能图形；
- 技能详情顶部各导航按钮、展开按钮、目标抗性/信息 Popover、各 Buff 批量按钮和添加 Buff 模式按钮；
- 技能详情计算乘区保留原 SVG 导航，在每个 SVG 节点正下方配置同尺寸真实液态玻璃取景层；旧 SVG 矩形只保留透明命中区，不绘制第二套边框；
- 批量 Buff 左侧工具按钮、右侧干员按钮与底部导航；
- 干员/Buff/武器/装备草稿操作组；
- 伤害表、PPT、图片管理器与常用弹窗中的独立操作按钮；标题栏、工具栏和列表行本身保持透明；
- 悬浮 Logo 与菜单。

大型列表项、工作流卡片、数据工具卡和整张表格不注册 WebGL；它们属于内容层。

## 性能运行时

`src/platform/theme/liquidGlassRuntime.ts` 统一管理真实玻璃的能力探测、质量档位与生成预算：

| 档位 | 触发条件 | 渲染像素比上限 | 大型承载层 |
| --- | --- | ---: | --- |
| `full` | 常规桌面环境 | 2 | 保留完整主题参数与 6 次高斯迭代 |
| `balanced` | Windows、内存不高于 4 GB 或逻辑核心不高于 4 | 1.25 | 全屏门板 15px、主要承载 12px、表格承载 8px |
| `compatibility` | 用户要求降低透明度，或高性能 WebGL 探测失败 | 1 | 关闭实时 `backdrop-filter`，使用主题实体底色和边框 |

- WebGL 只探测一次，探测 Canvas 随即主动释放；失败结果在主题重新进入时仍会恢复 `compatibility`，不会被主题初始化覆盖。
- 镜片组使用质量感知的小型生成池：`full` 最多 4 组并行、`balanced` 最多 2 组、`compatibility` 为 1 组。每组稳定后复制为普通 2D Canvas，并销毁渲染器和 WebGL 上下文；同一路由的固定镜片作为一个视觉批次同时揭示，不再逐组闪现。
- 固定控件先查内存 LRU，再查 IndexedDB PNG 快照。内存按数量和像素内存双重限额淘汰：通用控件最多 48 组 / 128 MiB，技能组合最多 8 组 / 64 MiB；持久层合计最多 96 组 / 192 MiB，按最近使用时间清理。缓存只保存光学画面，不保存用户业务数据。
- 通用控件以专用背景 Canvas 向着色器供图，因此依赖补丁会跳过目标 DOM 和静态前景的 `html-to-image` 捕获；文字、图标和业务状态仍由 DOM 实时绘制。这避免把已经固定的数据重复栅格化。
- 滚动和缩放采用 140ms 稳定窗口。移动期间保留旧镜片以避免高速滚动时出现空白，停止后才根据新几何生成一次替换画面。
- 依赖补丁仅在 `balanced` 档把 `@ybouane/liquidglass` 的高斯迭代从 6 次降为 3 次，同时关闭默认帧缓冲保留，并让库内部像素比与主题质量档位一致。补丁由根目录 `postinstall` 自动应用。
- 2026-08-02 本地真实数据抽查中，主排轴、干员配置和技能 / Buff 详情在稳定后都为 0 个活动渲染 Canvas、0 个 loading/fallback；详情页第二次打开时 7 组镜片在页面出现的同一批次全部命中内存缓存，整页刷新后 7 组全部命中持久缓存；干员配置第二次打开时 13 组全部命中内存缓存，稳定布局再次刷新后 13 组全部命中持久缓存。Windows 真机仍需作为发布前性能回归环境，不以 macOS 结果代替。

## 维护约束

1. 新增液态玻璃目标时，只注册实际交互按钮或有明确透视职责的业务图窗；不得注册包裹多个按钮的操作组、工具栏或标题栏。
2. 不允许为了折射增加可见的背景复制层；背景只能由不可见 Canvas 提供。
3. 不允许在阅读承载层内部再启用模糊。需要区分层级时使用透明度、边框、状态色和留白。
4. 不给干员、装备、武器、技能图标或其他彩色原图增加滤镜或统一蒙版。
5. 任何主题改动都要复核技能详情、添加 Buff、批量 Buff、数据表格、图片管理和 PPT，而不只看主排轴。
6. 低透明度环境使用实体降级；降级仍须保持内容可读和按钮状态可辨。
7. 纯布局 `div` 不得因为尺寸较大就自动升级为磨砂承载层；优先使用透明背景与可辨识边框。
8. 透明覆盖界面必须由一张全屏门板隔离下层内容；嵌套覆盖时由最上层门板接管，不叠加多张全屏模糊。
9. 计算摘要、计算行与 Buff 内容行属于文字层；允许分隔线，不允许再用半透明卡底和阴影模拟额外磨砂。
10. 乘区列表以滚动容器作为可见性锚点，一次注册全部 12 个真实玻璃目标；滚动期间沿用稳定镜片，停止后才校验几何并按需生成一次新记录，禁止逐滚动帧扫描或重绘。
11. 直接落在整屏磨砂承载层上的伤害组成、计算标签、公式值与 Buff 说明统一使用深墨文字；浅灰与浅紫只用于真实液态玻璃内部或明确的交互状态。
12. 固定镜片只能缓存真实着色器已经产出的画面，不能用 CSS 截图或磨砂替代；缓存键只包含折射实际依赖的视口、几何、镜片类型和材质，不得因异步加载的前景名称或图标误判失效。几何或材质变化后必须回到真实渲染器更新记录。
13. 恢复、保存、数据工作区和表格类页面采用“透明排列骨架 + 独立按钮镜片 + 一层阅读承载”的固定结构。关闭、本地、共享、SQLite、应用、导出、删除等按钮可以折射；说明、列表行、标题与工具条不可折射。
