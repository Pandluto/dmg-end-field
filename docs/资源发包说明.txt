终末地伤害工作台资源发包说明

适用范围

本说明用于发布桌面版和手机版共用的正式数据、图片资源。
资源直接部署到国内、海外服务器，不再通过 GitHub Release 提供。


一、发包前需要准备什么

1. 一份完整的 Share Data JSON

必须是当前工具导出的完整 Share Data，里面应包含：

干员资料库
武器资料库
装备资料库
Buff 资料库
共享排轴资料

不要使用 max.json、buff.json 等早期拆分文件，也不要把单独的 SQLite 备份当作资源包输入。

2. 一份完整图片目录

图片必须与 Share Data 属于同一批资料，并包含所有被资料引用的干员、武器、装备及技能图片。

工具可以识别以下目录形式：

assets/images
images
直接以各图片分类目录作为根目录

即使本轮只修改了数据、没有修改图片，也仍然选择完整图片目录。工具会通过内容哈希判断图片是否真的发生变化。


二、怎样生成资源包

1. 确认本地开发服务器已经运行。

常用启动命令：

npm run dev

本地地址固定为：

http://127.0.0.1:3030/

如果服务器已经在运行，不要重复启动。

2. 打开资源打包工具：

http://127.0.0.1:3030/#/settings/resource-packager

3. 选择完整图片目录。

4. 选择唯一一份完整 Share Data JSON。

5. 点击生成并下载。

工具会自动完成：

校验 Share Data 格式
识别图片根目录
检查资料引用的图片是否齐全
标准化正式资料
计算数据和所有图片的 SHA-256
生成确定性版本号
生成一个完整资源 ZIP

下载文件名称类似：

dmg-resource-release-20260809.9d9efd499c53.zip

相同的 Share Data 和图片会得到相同版本号。任何正式数据或图片发生变化，哈希版本都会变化。


三、生成后需要做什么

不要手工解压、修改或重新压缩资源 ZIP。
不要手工修改版本号、stable.json 或清单文件。
不要自行上传 GitHub Release。

直接把完整 ZIP 拖进 Codex，并发送：

发布这份资源，国内外一起部署，不走 GitHub Release。

如果浏览器因为重复下载给文件名增加了“(1)”等后缀，内容不会受影响，但建议只保留最终确认的一份，避免拿错文件。


四、Codex 会自动完成什么

1. 验证资源 ZIP 是否完整。

2. 验证版本号、数据 SHA-256、图片 SHA-256、图片引用和文件数量。

3. 将新版本与线上稳定版本比较。

如果版本完全相同，将停止重复发布并告知资源没有变化。

4. 将资源物化为服务器稳定通道和不可变版本目录。

5. 提交并推送本轮资源变更。

6. 从干净源码提交分别构建国内、海外产物，避免本地未跟踪文件污染构建结果。

7. 部署并验证国内服务器资源。

8. 部署海外 Sites，并验证海外独立图片交付。

9. 执行真实浏览器验收，包括：

桌面端首次安装
图片逐文件校验
离线冷启动
手机版最新数据加载
国内外资源版本一致性
缓存策略
Service Worker

10. 任意一路失败时停止发布或执行回滚，避免国内外长期处于不同版本。


五、怎样判断发布成功

Codex 的发布结果必须至少包含：

源码提交号
完整资源版本
数据版本
图片版本
海外 Sites 版本号
国内、海外正式访问地址
桌面端与手机版验收结果
国内、海外回滚点

国内外的 stable.json 必须指向同一个完整资源版本。

手机版必须读取线上最新版。

桌面版首次使用时可以自动安装正式资料；已有资料时，新版只下载并保存为带版本号的正式 Share Data，不得擅自覆盖用户当前正在使用的资料。


六、版本号怎样命名

完整资源版本格式：

日期.内容哈希前12位

例如：

20260809.9d9efd499c53

日期来自 Share Data 的 exportedAt，不是实际部署日期。

数据版本使用数据文件 SHA-256 的前 8 位。

图片版本使用全部图片路径、大小和 SHA-256 清单哈希的前 12 位。

哈希用于识别相同内容、避免重复版本和重复下载。它属于版本级去重，不是 ZIP 内部的增量或分块存储去重。


七、出现问题时怎么处理

打包阶段报错：不要绕过校验，先修正缺失图片或错误 Share Data，再重新生成。

版本号没有变化：说明输入内容与上一版相同，不需要重新部署。

日期前缀不符合预期：检查 Share Data 的 exportedAt 是否正确。

部署阶段失败：不要手工修改线上文件，交给 Codex 根据已保留的 Sites 版本和国内备份目录处理或回滚。

线上数据看起来没有更新：先核对 stable.json 的完整资源版本，再检查桌面端是否只是下载了新版但尚未由用户明确应用。


最简流程

选择完整图片目录
选择一份完整 Share Data
点击生成 ZIP
把 ZIP 交给 Codex
等待国内外部署和验收结果
