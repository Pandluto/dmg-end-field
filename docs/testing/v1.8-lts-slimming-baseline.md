- SkillButton 的单击/长按、Buff 增删与计层、Hit 启停、抗性和异常段；双击详情与重新进入已有浏览器覆盖。
- BuffBatch 的框选、批量增删、候选来源和取消恢复。

- SQLite 导出/导入、双标签占用/接管和真实断网后的 Service Worker 恢复；首次数据安装与编辑器刷新恢复已有浏览器覆盖。
- LTS 多主题整体页面可用性；SkillButton 的关键 DOM/SVG 标记已有默认主题覆盖。

## 测试策略

测试数量不是目标。测试必须锁定可观察行为，并与待拆模块的风险对应。

### A. 纯模型合同

优先把当前页面中的纯函数作为 characterization target：

- normalize 后的 schema 与默认值；
- workbook row/cell projection；
- formula binding 与编辑提交；
- share export/import round trip；
- explorer reorder 与 immutable update；
- SkillButton damage view model、Hit/异常段启停和计层派生；
- BuffBatch selection 与 pending add/remove 集合。

这些测试先基于当前 LTS 输入/输出建立，再移动实现。

### B. 浏览器流程

浏览器自动化至少覆盖：

1. 打开每个 lazy route，无白屏和 console error。
2. 各编辑器创建临时条目，保存、刷新、重新打开。
3. 各编辑器分享导出后重新导入，关键字段不变。
4. SkillButton 详情打开、Buff 操作、伤害值与重新进入。
5. 图片库选择用户/官方图片并刷新恢复。
6. SQLite 数据库导出/导入和页面恢复。

测试必须使用隔离浏览器 profile 和临时数据，不读取开发者真实 OPFS/站点数据。

### C. 平台终验

生产构建后在真实 Service Worker 控制下检查：

- 首次资料安装与 SHA-256 校验；
- 刷新后离线启动；
- 双标签写锁与显式接管；
- 失败更新不破坏上一版可用数据；
- SQLite 备份导入后重启恢复。

## AI 实施约束

- 测试基线提交与实现提交分离。
- 实现阶段不允许为了通过而降低断言、删除失败用例或改写 golden 数据。
- 若当前 LTS 行为本身被确认是缺陷，先单独记录产品决定，再以独立修复提交更新测试。
- 不写行数测试，不用源码字符串匹配代替行为；结构约束使用明确 import boundary 或 repository check。
- 每个模块只在对应快测通过后进入下一模块，最终再跑完整 `npm run check` 与真实浏览器终验。
